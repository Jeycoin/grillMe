# 拷问官 · AI 面试官

一个会**往死里追问**的 AI 面试官：实时语音对练、长期记忆、可加载牛客/小红书真实面经。

> 跟「参谋官」方向相反 —— 那个是帮你在面试里答题，这个是**反过来拷打你**。

## 它是怎么"拷打"你的

### 1. 人格引擎（`server/interviewer/persona.js`）

不是"你是一位面试官"这种废话 prompt。里面有：

- **四档压力**：模拟温和 → 大厂标准 → 高压面试 → 连环夺命
- **拷打技法库**：钉数字 / 钻漏洞 / 追三层 / 换条件 / 验真伪 / 设陷阱 / 沉默施压 / 撕简历
- **六种面试官类型**：技术专家、技术主管、交叉面、HR、老板终面、压力面
- **输出纪律**：强制口语短句、无 Markdown、一次只问一个问题、以问号结尾
  （这条是为了语音播报自然 —— 面试官说的是话，不是文档）

### 2. 阶段状态机（`server/interviewer/orchestrator.js`）

开场 → 简历项目深挖 → 技术八股 → 场景设计 → 算法手撕 → 行为面 → 反问 → 复盘

每阶段有轮数下限和目标，后台用快模型判断完成度决定是否推进；
某阶段拖太久会**强制推进**，不至于卡死在自我介绍。

### 3. 防死循环

高压模式下模型容易咬住一个点无限追问。编排器用字符 2-gram Jaccard
检测最近三问的相似度，连续两轮都超过阈值就注入系统提示强制换方向。

### 4. 长期记忆

```
data/
  profile.json      # 你的简历、目标岗位
  memory.json       # 薄弱项图谱（按 topic 聚合，重复错会加权上浮）
  sessions/*.json   # 每一场的完整问答与评分
```

下一场面试开场时，面试官会读到上次的薄弱项，**开场就朝那儿打**：
> "上次 Agent 和 RAG 你没答明白，今天先别绕。"

### 5. 评分报告

结束后输出：总分、结论、四维评分（技术深度/项目真实性/表达逻辑/抗压临场）、
亮点（引用你的原话）、薄弱点、可执行的改进建议、一段口语化的当面评语。

## 视觉规范

整体基调：**克制极简 · 沉静专业 · 轻科技感**。
参考 Linear 的克制布局、Notion 的柔和文字层级、Vercel 的安静氛围、ChatGPT 的对话亲和感。

### 色板（`web/src/styles.css` 的 `:root`）

| 角色 | 浅色 | 深色 | 用在哪 |
|---|---|---|---|
| 背景 | `#f7f8fa` | `#15171a` | 极浅冷灰白 / 深炭灰 |
| 表面 | `#ecf0f5` | `#1e2227` | 卡片、顶栏、侧栏（**比背景略深**） |
| 主文本 | `#1b1f24` | `#e7eaee` | 深炭黑 |
| 辅助 / 次要 | `#525b66` / `#67717c` | `#a2abb5` / `#838d98` | 靠灰度拉开层级 |
| 主色（灰蓝） | `#5d7085` | `#8ea4bb` | 结构、导航、选中态 |
| 强调色（薄荷青） | `#4b9c8e` | `#5cb3a3` | **只给确认/提交/高亮** |
| 危险 | `#a94a3c` | `#d98a7c` | 删除、错误、差评 |

### 三条硬规则

**1. 强调色是"正面"色，绝不能拿来标"差"。**
薄荷青的语义是"确认 / 提交 / 进行中"。低分、薄弱项、删除一律走 `--danger`。
这条踩过两次：报告页的 `overall` 低分、后台的 `score-pill.bad`，
原来都指向朱红（旧版 accent 恰好是红的，所以看不出问题）；
换成薄荷青后如果照搬，"差"会显示成一片绿，语义完全反掉。

**2. 弱项进度条是反着画的（沿用旧版结论）。**
`severity(score) = (10 - score) / 10` —— 分越低条越长。
所以填充色也要跟着反过来：分低 → `--danger`，分中 → `--warn`，分高 → `--accent`。

**3. 卡片靠表面色分层，不靠边框和阴影。**
卡片没有阴影，边框是 1px 极浅灰。层次由"表面比背景深一档"提供
（对比度约 1.08，再低就看不出来了）。阴影只留给真正悬浮的东西（抽屉、弹窗）。

### 对比度

小字（`--text-3`，11~13px）全部校准到 **≥ 4.5:1**，按钮文字 ≥ 5:1。
`--text-3` 一开始定成 `#8a939d` 只有 2.9:1，长时间读会累，后来调到 `#67717c`（4.67:1）。

### 主题

三态：浅色 / 深色 / 跟随系统，存在 `localStorage['kewenguan.theme.v1']`。
生效方式是往 `<html>` 写 `data-theme`，组件完全不感知主题。
`index.html` 里有一段**内联同步脚本**在首屏渲染前把值写上，否则会闪一下白底。

### 布局

面试页宽屏（≥1100px）是**双栏**：左边对话、右边作答台（语音状态 + 麦克风 + 输入框）。
窄屏自动回落成"对话在上、输入在底部"的单栏结构。

### 两个设计取舍

**1. 薄弱项的进度条是反着画的。**
0-10 分的得分里，分越低问题越严重，所以条要越长越红才符合直觉。
`score=1` 画成 90% 的红条（一眼看出是硬伤），`score=9` 画成 10% 的绿条。
如果按常规"分数越高条越长"来画，1/10 会显示成一个小点，看起来像"小问题"，语义完全反了。

**2. 面经素材从 localStorage 迁到了服务端（`data/materials.json`）。**
原来存在浏览器里，换设备就丢，手机上也看不到。现在统一落盘，
主站和后台共用同一份数据。前端如果检测到旧数据会自动提示迁移。

## 关于语音

技术路线是**级联**，不是端到端 S2S：

```
麦克风 → 16k PCM (AudioWorklet) → WAV → POST /api/voice/asr  → qwen3-asr-flash
       → LLM（人格 + 记忆 + 面经）
       → 流式断句 → 逐句 POST /api/voice/tts → qwen3-tts-flash → 排队播放（可打断）
```

选级联不选 `qwen3-omni-flash-realtime` 端到端的原因：**端到端塞不进人格、记忆和面经**，
而这三个恰好是这个产品的全部价值。`qwen3-tts-flash` 支持用 `instructions` 描述语气
（冷淡/打断/质疑），压迫感能显式调出来，端到端给不了。

> ⚠️ 早先这里写死的是 `qwen3-tts-instruct-flash`，但百炼上这个模型名已经不存在了，
> 请求直接返回 404 `Model not exist.`；而带语气的请求只在面试官开口时才发，
> 结果就是"文字全在、声音全没"。现在统一用 `qwen3-tts-flash`，并且失败会自动降级成
> 不带语气再合成一次（见 `server/voice/tts.js`），不会再整场冷场。
> 想换模型可以用环境变量 `TTS_MODEL` / `TTS_TONE_MODEL`。

### 压迫感是怎么"说出来"的

不靠模型自己揣摩，而是把压力档**显式翻译成 TTS 语气指令**（`persona.js` 的 `TONE_BY_PRESSURE`）：

| 压力 | 语气指令 |
|---|---|
| 1 模拟温和 | 平和、耐心、语速正常，像愿意给机会的前辈，句尾自然放松 |
| 2 大厂标准 | 专业、克制、略带审视，语速正常偏快，句尾干脆不拖长，不寒暄 |
| 3 高压面试 | 冷淡、急促、略带不耐，语速偏快，重音落在数字和质疑词上，情绪起伏很小 |
| 4 连环夺命 | 极冷淡、短促、平板，语速快，重音很重，几乎无情绪波动，像在审问 |

组装在**服务端**做（`routes/voice.js`）：前端只传 `pressure`，指令由服务端按档位取，
避免语气文案散落在前端被改乱。

### 三个必须自己踩过才知道的坑

**1. 整句 WASM 编码，不用 MediaRecorder。**
`MediaRecorder` 吐的是 webm/opus，ASR 接口对它支持不稳。改成 AudioWorklet 采 PCM
→ 盒式平均降到 16k → 手写 44 字节 WAV 头。30 行代码，省掉所有格式焦虑。
AudioWorklet 不可用时降级到 `ScriptProcessorNode`。

**2. 数字必须用 ITN 还原。**
兼容模式（`/compatible-mode/...`）**不支持** `asr_options`，实测把
"800 到 3000" 识别成 **"八点排到三千"** —— 对技术面试是灾难。
换成原生 `multimodal-generation` 接口 + `enable_itn: true` 后，
拿到的是 `QPS从800提升到3000，P99延迟从120ms降到35ms`。

**3. "面试官说完了"不能只看音频队列排空。**
LLM 是流式吐字的。如果它说完第一句后卡两秒再吐第二句，
音频队列会在这两秒里排空 —— 此时开麦，第二句会盖着用户的麦克风播出去，**抢麦**。
正确条件是 **文本流结束 + 音频队列排空** 同时成立才算说完
（`useVoice.ts` 的 `drainCheck()`）。
另外 `AudioQueue.stop()` **不能**触发 `onIdle`：打断不是"说完了"，
触发会让自动开麦逻辑误判。

### 自动播放策略

浏览器的音频上下文必须由**用户手势**唤起，但开麦是"面试官说完话"之后自动触发的（非手势）。
所以点「开始面试」时会先 `unlockAudio()` 把上下文唤醒，录音器后续复用它。
否则会出现"麦克风开了但一点声音都收不到"。

### 验证

```bash
curl http://127.0.0.1:8787/api/voice/health   # TTS 合成 → 反喂 ASR 的闭环自测
node scripts/voice-e2e.cjs                    # 真浏览器 + 假麦克风跑完整链路

# 视觉稿截图（浅色/深色、任意视口、整页）
node scripts/shot.cjs --url http://127.0.0.1:8787/ --out a.png --theme dark --size 1440x2100 --full
```

`scripts/voice-e2e.cjs` 用 `--use-fake-device-for-media-stream` 顶替麦克风，
通过 CDP 驱动真实页面，断言状态机流转：
**待机 → 面试官正在说 → 在听（自动开麦）→ 上传识别 → 空识别后自动重开麦**。

## 接入小红书 MCP

在项目根目录建 `mcp.json`（格式跟 Claude/Cursor 通用），把你现有的配置贴进去：

```json
{
  "mcpServers": {
    "xiaohongshu": {
      "command": "npx",
      "args": ["-y", "你的-小红书-mcp-包名"]
    }
  }
}
```

支持 `command`（stdio）和 `url`（streamable-http）两种传输。
保存后刷新页面 → 「面经库」→ MCP 标签 → 列出工具 → 调用 → 从返回内容抽题。

> 目前 env 里没找到小红书 MCP 的配置（WorkBuddy 侧未安装任何 connector），
> 需要你把自己的配置贴过来。`server/sources/mcp.js` 是自实现的轻量 MCP 客户端。

## 踩坑备忘

- **别用 `openai` SDK 的类型**推模型名，供应商模型列表实时变，一律运行时拉。
- `qwen3.8-flash` 做 brain 时响应快、追问狠，日常用足够了；`qwen3.8-max` 更适合收尾打分。
- 阶段判断用的 quick 模型**必须异步**，否则每轮问答都要多等一次往返。
